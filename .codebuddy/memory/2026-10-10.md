## GitHub Actions「检查B站新视频」AI分析 404 故障修复

- 现象：`scripts/analyze-video.js` 在 whisper 转录成功后调用 LLM 失败 `404 ERR_BAD_REQUEST`。
- 根因：中转站（默认 `https://token.sensenova.cn/v1`）上的模型 `deepseek-v4-pro` 已下线，返回 `model is not found`。密钥和 base URL 都有效（`/models` 能列出 7 个模型）。
- 当前可用模型：deepseek-v4-flash、deepseek-v4.1-flash、glm-5.2、kimi-k3、deepseek-flash、sensenova-6.8-flash-lite、sensenova-u1.5-lite。
- 处理：
  - 新增 `scripts/utils/llm.js` 统一 LLM 调用层（BASE_URL 规范化、401/403 快速失败、429 退避重试、模型 404 时自动从 `/models` 发现可用模型兜底、`cleanJSON` 兼容代码块包裹）。
  - 默认模型改为 `deepseek-v4-flash`；支持 `LLM_FALLBACK_MODELS` / `LLM_AUTO_FALLBACK=0` / `LLM_NO_JSON_FORMAT=1`。
  - `analyze-video.js`、`fetch-jin10.js`、`test-ai.js` 改为复用该模块；删除各自重复的 postWithRetry。
  - 新增诊断脚本 `scripts/check-llm.js`（npm run check-llm），check-bilibili.yml 增加「LLM 连通性诊断」步骤，并在跑 whisper 前做 preflight。
  - AUTOMATION.md 增加「LLM 配置与故障排查」章节。
- 注意：该项目中转站模型会不定期下线，下次再出现质量/可用性问题时先跑 `npm run check-llm` 看实时模型列表。

- UP 主：`1039025435` = 战国时代_姜汁汽水（82.4 万粉，地缘 + 财经，视频常超 15 分钟；已用 B 站 card API 核实）。
- 需求：不做 JSON、不入库 videos.json，只生成纯文字解读；文字过长按企微 4096 字节限制截断后推送。
- 实现（都在 `scripts/analyze-video.js`）：

  - 新增 `pushWechatPlain()` + `sendWechatMarkdown(content, webhook)`；截断工具抽到 `scripts/utils/text.js` 的 `truncateByBytes()`（按字节、按码点，避免乱码）。
  - 去重：文字模式用 `public/data/up_<uid>_state.json` 记录最近 100 条已推送记录，推送失败不记录（下次重试）。

- workflow `check-bilibili.yml`：timeout 15→60 分钟，`git add public/data/`，新增 EXTRA_UPS / EXTRA_UP_MAX_DURATION / EXTRA_UP_MAX_PER_RUN / EXTRA_WECHAT_WEBHOOK / WHISPER_MODEL 环境变量。
