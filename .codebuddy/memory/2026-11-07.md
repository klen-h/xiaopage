**改动**

  - 兼容：`structured.operation_advice` 保留，要求与 `advice_literal` 等值（前端 `AnalysisDetail.vue`、`build-views-lite.js` 仍在用）；`sentiment_score` 保留，语义收窄为"主市场情绪分，未表态=50"。

**两个关键决策**
1. **原文由脚本写入，不让 LLM 输出**：LLM 会改写、浪费 output token、且转录动辄上万字会撞 maxTokens。脚本手里本来就有 `transcript` 变量。
2. **正文外置、只留指针**：
   - 前端 `src/api/d1.ts` 是 `fetch('/data/videos.json')` 整包下载，6.4MB/532 条；内联原文会到 30MB+，首屏崩。
   - 放 `public/data/` 而非仓库根 `data/`：workflow 只 `git add public/data/`，放外面会**静默丢失**（日志正常、本地不报错）。

**videos.json 新增轻量字段**：`transcript_ref` / `transcript_chars` / `transcript_source`(`bilibili-subtitle`|`whisper-<model>`|`cached`) / `transcript_saved_at`。

**流程改动**
- `processSingleVideo`：拿到转录后**先存原文，再送 LLM** —— LLM 超时/拒答也不丢原文。
- `reanalyzeVideos`：先 `loadTranscript` 复用，命中则跳过下载 + whisper；写回时幂等补写上述字段（老条目重跑一次即补齐）。
- 新增 `--text <BV号>` 查看已存档原文。
- `--list-targets` 帮助补了 `--reanalyze` / `--text` 两行。
